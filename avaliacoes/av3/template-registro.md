**Limites e condição para rever:**
- **Comparação de tipos:** `get_pedido` compara `usuario_id` por `!=`. Se uma camada HTTP real passar ids como texto (`"20"` × `20`), o próprio dono recebe 404. A falha é fechada (nega acesso), mas é um defeito; o contrato e a suíte só usam inteiros.
- **Sem autenticação real:** não há autenticação no caso (`regras.md`), então `usuario_id` é confiado a quem chama. R4 vale só se essa camada for honesta.
- **Mutação:** cobre os operadores da ferramenta, sem mutante para a nova checagem (as sabotagens suprem isso) e sem `calculo.py`. O comando padrão da ferramenta falha no Windows (`shlex.split` remove as `\` de `sys.executable`), então rodei com `MINILOJA_TEST_CMD` usando barras normais.
- **Fora do alcance:** canal de tempo (diferença de latência entre existente e alheio) não foi medido, e não faz sentido num repositório em memória.
- **Medição:** o contexto de time é genérico, e o baseline do curso tem n = 1, mostrando direção e não tamanho do ganho.
- **Revejo se:** o contrato passar a definir 403 ou um papel de administrador que veja pedidos de outros; surgir um novo handler que leia pedidos; ou a camada HTTP passar ids como texto.
